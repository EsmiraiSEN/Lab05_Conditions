## 💻 Фрагмент кода: функция `GetHint()`

```csharp
static string GetHint(int diff)
{
    switch (diff)
    {
        case <= 3:
            return "Горячо!";
        case <= 10:
            return "Тепло!";
        default:
            return "Холодно!";
    }
}
```

> 💡 **Как это работает:** функция принимает разницу между загаданным числом и попыткой игрока.  
> Если разница ≤ 3 — «Горячо», если ≤ 10 — «Тепло», иначе — «Холодно».

## 🧠 Главные выводы

1. **Условные конструкции — основа логики программ.**  
   Без `if/else` и `switch` невозможно построить программу, которая реагирует на действия пользователя.

2. **Выбор конструкции зависит от задачи.**  
   Для простых случаев «одно из двух» удобен тернарный оператор, для сравнения одной переменной с несколькими значениями — `switch`, а для сложных составных условий — `if/else if`.

3. **Безопасность важнее краткости.**  
   `int.TryParse()` вместо `int.Parse()` позволяет избежать падения программы при некорректном вводе.

4. **`break` в `switch` обязателен.**  
   Без него выполнение «проваливается» в следующий `case`, что приводит к неверной логике.

## ❓ Ответы на вопросы

### 1. Чем `int.TryParse()` безопаснее `int.Parse()`?

`int.Parse()` выбрасывает исключение `FormatException`, если строка не является числом. Это приводит к аварийному завершению программы.

`int.TryParse()` возвращает `true` или `false`, а результат записывает в `out`-параметр. Если преобразование не удалось — программа продолжает работу.

**Когда использовать:**
- `int.Parse()` — когда данные **точно корректны**.
- `int.TryParse()` — когда данные вводит **пользователь**.

---

### 2. Когда `switch` удобнее, чем цепочка `if/else if`?

`switch` удобнее, когда нужно сравнить **одну переменную** с несколькими **конкретными значениями**.

**Пример из жизни:** меню банкомата.
- 1 — снять наличные
- 2 — пополнить счёт
- 3 — проверить баланс
- 4 — перевести деньги

Вместо длинной цепочки `if` удобнее использовать `switch`.

---

### 3. Что произойдёт, если убрать `break` в `switch`?

Произойдёт **«проваливание»** (fall-through): после выполнения текущего `case` программа выполнит и следующий `case`.

**Исключение:** намеренная группировка `case` без кода между ними:

```csharp
case 1:
case 2:
case 3:
    Console.WriteLine("Рабочий день");
    break;
```

---

### 4. Чем отличается `=` от `==` в C#?

- `=` — оператор **присваивания**: `int x = 5;`
- `==` — оператор **сравнения**: `if (x == 5) ...`

**Почему это частая ошибка:** в математике `=` означает сравнение, а в C# — присваивание. Новички часто путают эти операторы.

---

### 5. Можно ли вложить тернарный оператор в другой тернарный оператор?

Да, можно.

**Пример из лабораторной:**

```csharp
string hint = diff <= 3 ? "Горячо!" : (diff <= 10 ? "Тепло!" : "Холодно!");
```

**Оценка читаемости:** код компактный, но **менее читаемый**, чем `switch`.  
Если вложенность больше двух уровней — разобраться сложно.  
Лучше использовать `switch` или `if/else`.
